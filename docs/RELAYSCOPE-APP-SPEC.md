# RelayScope 应用产品与交互规格

> 版本：v1.0
> 状态：前端与核心后端已完成首版，持续迭代中
> 用途：作为产品、前端、Android、后端、OCR 和视觉审查 AI 的统一上下文

## 1. 产品定位

RelayScope 是一个 **API 中转站测速与管理工具**，用于比较多个 OpenAI 兼容中转站的真实表现。

它帮助用户回答：

> 哪个中转站当前最稳定、最快、模型最全、余额实际消耗最少？

RelayScope 不是聊天软件，不是代理转发服务，也不是多用户管理后台。核心工作流是：

```text
添加中转站
→ 输入网址和 API 密钥
→ 测试连通、首包、流式和模型可用性
→ 录入或识别价格与站内余额扣费倍率
→ 计算真实成本
→ 查看排行榜
→ 复制最优站点配置
→ 按自定义间隔自动巡检
```

## 1.1 前端实现硬规则

浏览器前端原型是已经确认过的唯一视觉基准：

```text
/workspace/api-relay-tester-prototype/index.html
```

正式 Android App 不得再用 Java 原生控件重新仿做一套界面。正确路线是：

```text
同一套 HTML/CSS/JS
→ 放入 Android assets
→ WebView 加载本地前端
→ JavaScript Bridge 接入原生能力
```

这样浏览器看到的前端和 APK 里的前端保持一致。原生层只负责：

- Android Keystore 密钥存储；
- 真实网络测速；
- OCR 图片选择与本地识别；
- 前台巡检服务和通知；
- 文件选择、复制和系统能力。

禁止出现“浏览器版一套、Android 原生重画一套”的双前端分叉。

## 1.2 演示数据隔离规则

演示站点、固定测速数据、固定价格、固定成本和假矩阵只能存在于：

- 浏览器设计原型；
- 明确标记的开发演示模式；
- 视觉审查用的测试夹具。

正式 APK 默认不得内置或展示这些演示站点。首次启动应显示真实空状态，引导用户：

```text
还没有中转站
→ 添加第一个站点
```

正式应用中的排行榜、模型矩阵、价格和成本只能来自用户保存的数据或真实请求结果。任何演示开关必须显式命名为 `demo`，默认关闭，不能把演示数据混入生产状态。

## 2. 核心功能

### 2.1 四层测速

1. **连通性**：请求 `/v1/models`，判断网址和 API 密钥是否可用；
2. **首包延迟**：记录 `/v1/models` 请求的 TTFB；
3. **流式质量**：向模型发最小流式请求，记录首 token 响应时间；
4. **模型真实可用性**：从模型列表逐个发最小请求，不把“出现在列表里”误判为真实可用。

错误必须分类显示：

```text
认证失败
接口/模型不存在
限流
服务端错误
网络错误
超时
流式空响应
部分可用
```

手动全站测试逐个检查模型。后台定期巡检使用低成本模式：`/v1/models` 加一个代表模型的流式请求，不默认逐模型全测。

### 2.2 排行榜

总览按综合结果排序，站点卡片显示：

- 排名；
- 站点名称；
- 状态标签；
- 首包延迟；
- 流式速度或首 token；
- 可用模型数量；
- 按余额扣费倍率折算后的实际成本；
- 综合评分和进度条；
- 复制配置入口。

第一名使用青绿色推荐视觉，但不能夸张发光。尚未测试的站点必须显示“待测试”，不能伪装成正常站点。

### 2.3 模型可用性矩阵

横向比较站点，纵向比较模型：

```text
模型                  星河 API       北极光       备用站       最佳
gpt-5.6-terra          可用           可用         限流         星河
claude-sonnet-4        可用           不支持       可用         星河
deepseek-v3            可用           可用         可用         星河
gemini-2.5-pro         波动           可用         不存在       北极光
```

矩阵必须区分：

- `可用`：浅青绿色；
- `限流 / 429`：黄色或红色；
- `不支持 / 404`：红色；
- `波动 / 503`：黄色或红色；
- `模型不存在`：红色；
- `网络错误`：红色。

页面说明：

```text
状态来自逐模型真实请求，不只看 /v1/models 列表。
```

移动端允许矩阵内部横向滚动，但整个 App 不应横向溢出。

### 2.4 价格与站内余额扣费倍率

这里的“倍率”专指：

> 站内模型的余额扣费倍率

不是官方价格加价倍数。

每个模型记录：

```text
模型名
输入价格 / 1M token
输出价格 / 1M token
缓存价格（可选）
币种
站内余额扣费倍率
价格来源
更新时间
```

实际成本：

```text
实际输入成本 = 标价输入价格 × 站内余额扣费倍率
实际输出成本 = 标价输出价格 × 站内余额扣费倍率
```

价格来源必须展示：

```text
自动拉取 · 2小时前
截图识别 · 已确认
截图识别 · 待确认
本地手动 · 已保存
获取失败 · 使用旧价
```

完整价格源失败或字段不完整时，不覆盖旧数据。

### 2.5 自动拉取价格

用户添加站点时可以填写可选的价格源 JSON URL。

通用适配器尝试识别：

- 顶层数组；
- `data` 数组；
- `models` 数组；
- `prices` 数组；
- `model`、`model_name`、`id`、`name`；
- `input`、`input_price`、`prompt`；
- `output`、`output_price`、`completion`；
- `multiplier`、`ratio`、`倍率`。

价格源请求必要时带当前站点的 Bearer API 密钥。只有完整有效的价格行才写入本地；无法识别时提示使用截图或手动录入。

### 2.6 截图 OCR 录入

截图价格识别必须遵守：

```text
上传截图
→ 手机上的 OCR 识别
→ 提取模型名、输入价、输出价、余额扣费倍率
→ 检查字段完整性
→ 完整：打开可编辑确认表
→ 不完整：要求补传局部截图或改用手动录入
→ 用户确认后才保存
```

OCR 不得：

- 识别后直接覆盖已有价格；
- 看不清时默认倍率为 `1×`；
- 把不确定数据标为已确认；
- 隐藏识别来源。

不完整时的提示示例：

```text
截图信息不完整

无法确认：输出价格、余额扣费倍率

请补传包含这些字段的局部截图，
或者改用手动录入。
识别结果不会自动覆盖价格。

[手动录入] [补传局部截图]
```

当前使用 Android ML Kit 中文文字识别，图片在手机本地处理，不上传服务器。

### 2.7 手动价格录入

手动录入至少包括：

```text
模型名
输入价格 / 1M
输出价格 / 1M
站内余额扣费倍率
币种
```

输入必须校验：

- 模型名不能为空；
- 输入价和输出价不得为负数；
- 余额扣费倍率必须大于 0；
- 非法数字不得保存。

### 2.8 真实成本试算器

输入：

```text
输入 token（万）
输出 token（万）
```

输出不同站点的实际预计扣费，并显示站内倍率。

底部必须有：

```text
试算仅用于比较，实际扣费以站点账单为准。
```

### 2.9 定期巡检与变更提醒

巡检间隔由用户自由输入：

- 支持任意正数；
- 支持小数；
- `0.1 分钟 = 6 秒`；
- 5、15、30、60、180 分钟只是快捷填充；
- 不能限制只能选择固定值；
- 修改间隔后必须真正重启调度服务；
- 价格或倍率变化、最优站变化、站点掉线时提醒。

实现采用 Android 前台服务，不使用 WorkManager 作为精确定时器，因为 WorkManager 有约 15 分钟周期限制。

前台服务的真实限制：

- 需要常驻通知；
- Android 14/15 需要匹配前台服务类型权限；
- Android 13 可能需要通知权限；
- 厂商省电策略可能杀后台；
- `START_STICKY` 不是绝对保证；
- 高频巡检会增加请求和余额消耗。

因此 UI 文案只能说“按设置尽量运行”，不能保证系统层面的绝对准时。

## 3. 视觉设计系统

### 3.1 视觉方向

整体是深色网络监控控制台：

```text
API 监控台
网络诊断
中转站体检
稳定性排行
数据优先
```

要求：

- 专业、克制、工程化；
- 不像聊天软件；
- 不使用营销插画；
- 不使用大面积紫色；
- 不使用无意义的大渐变；
- 信息密度适中；
- 重点突出状态、数字、故障原因。

### 3.2 颜色

```text
页面背景       #0E151B
卡片背景       #172129
次级卡片       #1D2A33
边框           #30404A
主要文字       #EDF4F3
次要文字       #8FA0AA
主强调色       #4CE0CA
浅青色文字     #A5F5E8
警告色         #FFCC70
错误色         #FF7D80
```

颜色语义：

- 青绿色：正常、可用、推荐；
- 黄色：慢、波动、待确认、倍率偏高；
- 红色：认证失败、限流、模型不存在、服务错误。

### 3.3 布局

移动端优先，单列布局，建议最大宽度 700px：

```text

↓

↓
总览 / 模型矩阵 / 价格与倍率 / 成本试算
↓
当前功能页面
↓
定期巡检区域
```

卡片圆角建议 15–18px，边框细、对比度适中，页面四周要有留白。

## 5. 本地数据与隐私

### 5.1 API 密钥

API 密钥只保存在 App 私有目录，当前使用 Android Keystore 的 AES-GCM 加密。

数据流程：

```text
输入明文密钥
→ Android Keystore AES-GCM 加密
→ SharedPreferences 保存密文
→ 请求时解密到内存
→ 放入 Authorization Bearer 请求头
```

密钥不得：

- 进入 Git；
- 进入 GitHub Actions；
- 进入日志；
- 进入错误提示；
- 上传到价格源以外的服务器。

### 5.2 价格数据

价格数据保存在本地，包括：

- 模型名；
- 输入价；
- 输出价；
- 倍率；
- 币种；
- 来源。

不完整的自动或 OCR 识别结果不得覆盖已保存价格。
